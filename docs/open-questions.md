# 未确认规则与当前隔离方式

以下均不是产品已确认的地方规则。当前服务端使用 `CardCombinationFinder.demo()`，所有状态返回 `policy: demo-v1`；界面大厅也明确显示演示规则。可以替换策略实现，不能直接把演示策略当成最终规则。

| 待确认项 | 当前演示行为 | 扩展位置 / 影响 |
|---|---|---|
| 单张/对子/三张普通点数完整顺序 | 3…K,A,2 | `Card.strength`；比较与提示 |
| 癞子任意点数、花色、多癞子限制 | 两张王均可代表 A…K 点数，无花色身份 | `WildcardPolicy`；所有牌型。`unconfirmed()` 拒绝未确认的替代并有测试 |
| 炸弹张数及硬炸/软炸比较 | 恰好四张同点数，软硬等价，按普通点数比较 | `BombPolicy`；压制与冲正。`unconfirmed()` 只认天然四张、不定义炸弹相互大小 |
| “2 炸弹”具体构成 | 演示配置暂以主体点数 2 识别 | `BombPolicy.isTwoBomb`；档位 4 记分。严格占位对未确认判断抛出明确异常 |
| 顺子、连对、飞机的完整连续边界 | 序列 A,2,3,…,K；不跨 K 回 A | `SequencePolicy.order`；例如 QKA、JQKA2 是否有效仍须确认 |
| 不同长度飞机及附件比较 | 暂只允许相同结构/长度，按主体起始序列位置比较，不比较附件 | 独立 `PlanePolicy`；需最终产品规则 |
| 666 是否有飞机特殊含义 | 按三不带；未扩展为飞机 | `Combination.Type` / 模板生成入口。可增加独立地方规则识别器 |
| 不同牌型提示顺序 | 使用枚举顺序：单、对、三、三带散、三带对、顺、连对、三类飞机、炸弹 | `HintComparator` 可注入顺序；同牌型按长度、比较值、稳定 key。炸弹顺序仅是演示选择 |
| 有合法出牌时超时怎么办 | 归零后等待，绝不自动过牌 | `TimeoutPolicy.awaitPlayer`；已有 opt-in 合法首候选托管策略测试，默认服务端不启用托管 |
| 黑桃 3 正好落入两张弃牌 | 首局重新洗牌直到黑桃 3 发给玩家 | `Game.deal`；这是满足首出条件的明确演示兜底，必须向产品确认 |

未确认项不会阻止其他模块开发。不可通过把 `unconfirmed()` 与演示记分混用来声称已有完整最终规则。
